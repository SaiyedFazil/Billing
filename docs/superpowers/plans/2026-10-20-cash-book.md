# Cash Book Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An owner-only Cash book page that shows money in (completed bills) beside money out (owner-entered expenses), each split cash / online, with expense entry, audited edits, cancellation and owner-managed expense categories.

**Architecture:** Two new tables, `expense_categories` and `expenses`, both protected by delete-blocking triggers; a cancelled expense is frozen by a trigger. Pure helpers in `src/lib/utils/cash-book.ts` map modes to groups, merge per-day bill and expense totals, and derive the summary from those day rows, so the KPIs always equal the sum of Day by day. The page lives under `/administration`, guards itself, and keeps range, tab, filters and page in the URL, like the Bills ledger.

**Tech Stack:** Next.js 16 App Router, Drizzle + Neon (`neon-serverless` Pool), Zod 4, big.js via `money.ts`, Tailwind v4 + shadcn/ui (Ember tokens), tsx verify scripts (no test framework).

**Spec:** `docs/superpowers/specs/2026-10-20-cash-book-design.md`. Read it alongside this plan. § numbers below refer to it.

## Global Constraints

- Branch `feature/cash-book` (the spec is already committed there). Commit each task separately, after `npm run typecheck` and `npm run lint` pass.
- Every new server action calls `requireSuperadmin()` on its first line inside `guarded()`. The page calls `requireSuperadmin()` itself before any query (non-negotiable 2).
- Money is a decimal string end to end. No `number` in an amount path, no `z.number()` for an amount. SQL sums are returned `::text` and passed through `toAmount()`. Arithmetic goes through `money.ts`. Display uses `formatINR()` with `tabular-nums`. The only exception is share-bar widths, which may use `Number()` with a display-geometry comment.
- Never `DELETE` an expense or an expense category. Cancel or retire instead. Triggers enforce this.
- "Today" and "future" mean the **shop's** date: `businessDate(new Date(), await getShopTimezone())`.
- Limits: category name 1–40 chars; `paid_to` ≤ 80; `note` ≤ 200; `cancel_reason` 1–200; amount > 0 and ≤ `MAX_EXPENSE = "1000000.00"` (₹10,00,000, our cap per §7).
- Seeded categories, in this order: Raw materials, Vegetables & dairy, Gas, Packaging, Salary, Rent, Electricity, Repairs & maintenance, Other.
- Labels: modes `Cash`, `UPI`, `Card`, `Bank transfer`; groups `Cash`, `Online`, `Other`. Never call Net "profit".
- Group dots reuse the chart tokens: Cash `bg-chart-1`, Online `bg-chart-2`, Other `bg-chart-4`. No new hex.
- Exact copy:
  - `The date can't be in the future`
  - `That category was retired. Choose another.`
  - `That expense no longer exists.`
  - `That expense was cancelled, so it can't be changed.`
  - `That expense is already cancelled.`
  - `That category no longer exists.`
  - `Keep at least one category, or there's nothing to file expenses under.`
  - `Enter an amount above ₹0`
  - `That's more than ₹10,00,000. Check the amount.`
- After every new shadcn component: `npm run format`, then restyle it to the tokens.

## Review Focus

1. **Junk in the amount box** (`""`, `"0"`, `"0.00"`, `"-5"`, `"1.005"`, `"1e3"`, `"1,250"`, `" 250 "`, `"1000000.01"`). Expected: an inline error, except `" 250 "`, which saves as `250.00`. Pinned in Task 2 (schema checks).
2. **An entry near midnight.** At 00:30 IST the server's UTC date is still yesterday. Expected: today (IST) is accepted and tomorrow (IST) is refused. Pinned in Task 2 (`isFutureDate`) and Task 3 (service checks built from `businessDate` and `shiftIsoDate`).
3. **A slow network and a second tap on Save, or a retry carrying different values under the same key.** Expected: exactly one expense, holding the first values. Pinned in Task 3.
4. **A day with only expenses, a day with only "Other" bills, or a negative net.** Expected: the day still appears, "Other" counts in the total net, the minus sign shows, and the KPIs equal the sum of the Day by day rows. Pinned in Task 2 (`buildCashBookDays` / `summarizeCashBook` fixture).
5. **Editing an old expense whose category was later retired.** Expected: it saves keeping that category; switching to a _different_ retired category is refused. The retired name still shows in the list and in Spend by category. Pinned in Task 3 and Task 4.

  - **`retireExpenseCategory(id: string, userId: string): Promise<ActionResult<null>>`**
